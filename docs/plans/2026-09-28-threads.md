## Дизайн

```
лента канала (CRT on: только корни; CRT off: ответы inline со строкой «Ответ <автору>: …»)
   корень: «N ответов · <время последнего>»  ─┐
   ↩ в панели действий (горячий пост)         ├─► OpenThread(srv, channel, root) ──► ThreadPane справа
   клик по уведомлению об ответе             ─┘            │
                                                           ▼
Go state.Server: кэш тредов (открытый + 2 недавних, ≤200 ответов, только память)
   GET /posts/{root}/thread?perPage=60&direction=up&collapsedThreads=<crt>   (последние 60 + корень)
   старше: …&fromCreateAt=<старейший>&fromPost=<его id>                       (при прокрутке вверх)
   WS posted/post_edited/post_deleted/reaction_* → и окна каналов, и кэш тредов → thread_changed
   CRT: PUT /users/me/teams/{team}/threads/{root}/read/{ts} — панель открыта И окно в фокусе
   CRT: бейджи += упоминания в тредах (teams/unread?include_collapsed_threads, threads?totalsOnly; thread_updated/thread_read_changed)
```

Решения контроллера (пользователь не уточнял — в реестре SDD как Ruling):

- **Кэш тредов — в `state.Server` под `s.mu`**, не отдельный пакет: события WS применяются к окнам каналов и к тредам одной операцией, как сейчас к окну и `s.older`.
- **Граница памяти (явная).**
  - Держится не больше `ThreadCacheSize = 3` тредов на сервер: открытый + 2 недавних (LRU).
  - В каждом — корень и не больше `ThreadMaxReplies = 200` ответов.
  - Закрытие панели делает тред «недавним» и обрезает его до последней страницы (`ThreadPage = 60` ответов). Вытесненный из LRU тред освобождается целиком.
  - Кэш не пишется в снимок. Он очищается при остановке воркера (выход, смена пользователя), смене CRT (`ResetThreads`), уходе из канала (`forgetChannelLocked`).
  - Черновики тредов — только в памяти, не больше `ThreadDraftCap = 50` (вытесняется самый старый).
  - Итог: ≤ ~1 МБ кучи на сервер, роста со временем нет.
- **Потолок 200 ответов.** Прокрутка вверх догружает страницы по 60, пока тред не достигнет 200 ответов. Дальше подгрузки нет, вверху строка «Показаны последние 200 ответов» со ссылкой «Открыть в браузере» (permalink `…/<team>/pl/<root>` через `OpenURL`). Новый живой ответ в треде на потолке вытесняет самый старый.
- **Загрузка.** Никогда не звать `GET /posts/{id}/thread` без `perPage`: сервер отдаст тред целиком. Всегда `direction=up` (новейшие первыми), `perPage=60`, `collapsedThreads=<crt>`; `order[0]` — всегда сам корень; `has_next` — есть ли старше. Параметры проверены по `server/channels/api4/post.go:760–880` и `store/sqlstore/post_store.go:575–897`: `fromPost` требует `fromCreateAt`; при `collapsedThreads=true` id обязан быть корнем.
- **После разрыва WS** все треды кэша помечаются устаревшими (`stale`). Открытый тред после bootstrap перечитывает последнюю страницу. Правило слияния — как у `SetWindow`: ответы новее страницы сохраняются; история, до которой страница не дотянулась, отбрасывается (дыра). Остальные треды перечитываются при открытии. `updatesOnly` не используется: он не видит удалений.
- **Панель.**
  - Справа от ленты, ширина 420 px. При ширине окна меньше 1024 px панель перекрывает ленту (вариант C спайка как режим узкого окна) с кнопкой «← К каналу».
  - Закрывается по `×`, Esc (фокус в панели, нет открытого поповера), смене канала или сервера. Тред остаётся в LRU для быстрого повторного открытия.
  - Открытие другого треда заменяет текущий.
  - Внутри панели: корень, разделитель «N ответов», ответы, свой `Composer`. Нет «↩», нет «N ответов» под корнем, нет линии «новые», нет Follow и аватаров участников (позже).
- **Удалённый корень** (событие или 404 при загрузке): панель остаётся открытой с баннером «Исходное сообщение удалено», композер выключен.
- **Отправка ответа** — отдельная привязка `SendReply` (у `SendPost` сигнатура не меняется). Pending-ответ живёт в `s.pending[channel]` с `RootID`.
  - При CRT он виден только в панели (исправление T7).
  - Без CRT — и в ленте, и в панели.
- **Вложения и черновик ответа** — по ключу (канал, корень). Методы вложений и browser-маршрут получают `rootID` (`""` — композер канала). Drop-цель панели несёт `data-root`. Вложения треда не могут уйти в пост канала, и наоборот (`Take` по ключу).
- **Лента.**
  - Под корнем с `reply_count > 0` (оба режима) кликабельная строка `«N ответов · последний ответ <время>»`, `aria-label`.
  - Кнопка `IconReply` в слоте `{replyButton}`: у корня открывает его тред, у ответа (CRT off) — тред его корня (ответ на ответ сервер запрещает). Её нет у pending/failed/системных постов.
  - CRT off: у первого ответа серии (предыдущая строка ленты — не этот корень и не ответ в тот же тред; как `isFirstReply` веб-клиента) — строка контекста «Ответ <автору>: <фрагмент корня>». Строка кликабельна (открывает тред). Автор и фрагмент (≤ 80 рун, пробелы схлопнуты) даёт Go из того, что держит (окно, история, кэш тредов). Корня нет — «Ответ в треде», без дополнительного запроса.
- **Счётчик ответов корня.**
  - Берётся из `reply_count` самого `posted`-ответа: сервер кладёт туда актуальное число (`post_store.go:276–292`). Присваивается, только если `create_at` ответа ≥ `LastReplyAt` корня; иначе, и при `reply_count == 0`, как раньше — `++` для нового id.
  - Удаление ответа уменьшает счётчик ровно один раз на id (кольцо `gone`, как `seen`), не ниже 0.
  - `SetWindow`/`upsertLocked` сохраняют локальные `{ReplyCount, LastReplyAt}`, если локальный `LastReplyAt` > `UpdateAt` пришедшего корня. Сервер двигает `UpdateAt` корня на время каждого ответа (`post_store.go:270–274`), так что страница старше живого ответа.
- **Прочтение треда (только CRT).**
  - `PUT …/users/me/teams/{team}/threads/{root}/read/{ts}` шлётся, пока панель открыта и окно в фокусе (фокус — только у активного сервера, как у каналов): при открытии, при получении фокуса, на новый чужой ответ в открытом треде, на `thread_updated` открытого треда.
  - Один запрос на тред за раз, с перепроверкой после (как `Worker.view`).
  - `team` — команда канала, у DM/GM — текущая команда. `ts = max(now, create_at новейшего ответа в кэше)`.
  - 404 (нет подписки на тред) — молча, и больше не слать для этого открытия, пока не придёт свой ответ или `thread_updated` этого треда.
  - Без CRT треды отдельно не читаются: `view` канала делает всё на сервере.
- **Упоминания в тредах в бейджах (только CRT).**
  - Читаются в `fetchMeta` (под тем же guard обновления, что и каналы): `GET /users/me/teams/unread?include_collapsed_threads=true` (`thread_mention_count` по командам, без DM/GM-тредов) и для DM/GM-части — `GET /users/me/teams/{nav team}/threads?totalsOnly=true` минус тот же запрос с `excludeDirect=true`, не ниже 0.
  - Дальше — дельты `unread_mentions − previous_unread_mentions` из `thread_updated` (ключ — `broadcast.team_id`, `""` у DM/GM) и `thread_read_changed`.
  - `thread_read_changed` без `thread_id` (прочитаны все треды команды или канала) — фоновое перечитывание итогов.
  - Итоги не ниже 0. Ответ самого `PUT read` счётчики не трогает — только событие (иначе двойной учёт).
  - Бейдж сервера = упоминания каналов + Σ по командам + DM/GM-часть; строка команды = её каналы + её треды.
  - Непрочитанные треды **без** упоминаний бейдж «непрочитано» не поднимают: без вида «Треды» их негде снять.
  - Упоминание в треде поднимает бейдж сервера и команды, но не строку канала: итоги сервера — по командам, не по каналам. Найти тред можно по уведомлению или по «N ответов». Привязка к строке канала — в бэклог. Решено контроллером, пользователь может пересмотреть до Task 5.
- **Уведомления.**
  - Уведомление об ответе (оба режима) несёт `root_id`; его `ID` — `mm-<srv>-<channel>-<root>`, серия ответов одного треда склеивается отдельно от канала.
  - Клик открывает канал, затем панель треда.
  - `notify.Decide`: CRT-ответ в открытом треде при фокусе не уведомляет (`thread_is_open`).
- **Исправления CRT из спайка §4.1 и T7:**
  - п.4 — свой CRT-ответ не трогает `Member.MsgCount*`/`LastViewedAt`;
  - п.5 — `Bootstrap` сравнивает `crtLocked()` до/после и сообщает о смене → `ResetWindows` + `ResetThreads` + `enqueueAll` (закрывает и снимок, поднятый в другом режиме);
  - п.6 — pending-ответы вне ленты при CRT, `reply_count` из `posted`, уменьшение при удалении, `SetWindow` не затирает более новый счётчик;
  - п.7 — `NeedsView` при CRT смотрит только корневые счётчики.
- **Старт не блокируется ничем новым.** Кэш тредов не восстанавливается из снимка. Итоги тредов читает воркер в своей горутине в составе `fetchMeta`, до них бейдж — без тредов. Ни одного нового синхронного вызова на старте.

- `build/bin/spk-mm-client-desktop` не пересобирать; проверочные сборки — под `.agents/tmp`.
- Скриншоты — browser mode на своём порту, в `.agents/tmp/threads/`.
- Замеры памяти — headless (`xvfb-run -a`, `TMPDIR` в scratch).
- Задачи с пометкой **(opus)** — чувствительные к конкурентности Go: контроллер отдаёт их opus.

## Review Focus

1. **Двойной или потерянный счётчик ответов.** Свой ответ приходит дважды (REST `CreatePost` + эхо WS), удаление — тоже дважды (REST `DeletePost` + `post_deleted`). Страница REST, пришедшая после живого ответа, не должна откатывать счётчик. — Task 2: `TestReplyCountComesFromPostedOnce`, `TestReplyDeleteDecrementsOnce`, `TestSetWindowKeepsNewerLocalReplyCount`.
2. **Рост памяти.** Открыть и закрыть 20 тредов по 250 ответов, переключить CRT, остановить воркер — кэш держит ≤ 3 тредов, ≤ 200 ответов в каждом, закрытый обрезан до 60, черновики ≤ 50, после остановки пусто. — Task 3: `TestThreadCacheStaysBounded`; Task 4: `TestThreadDraftsAreBounded`; память — Task 7.
3. **Ответ, потерянный в разрыве или гонке.** Ответ пришёл по WS, пока летела первая страница треда, или в дыру между потоками. После bootstrap открытый тред должен его показать, ничего не задвоив и не потеряв pending. Страница, запрошенная до `ResetThreads` или вытеснения, не должна воскресить тред. — Task 3: `TestThreadPageKeepsRepliesThatArrivedInFlight`, `TestOpenThreadCatchesUpAfterGap`, `TestLateThreadPageAfterResetIsIgnored`.
4. **Прочтение «за спиной» пользователя.** Тред не должен помечаться прочитанным при окне без фокуса, на фоновом сервере или при закрытой панели. 404 (нет подписки) не должен давать запрос на каждый ответ. — Task 5: `TestThreadReadOnlyWhileOpenAndFocused`, `TestThreadReadNotFollowingIsNotRepeated`.
5. **Дрейф бейджа упоминаний в тредах.** События, придержанные на время `fetchMeta`, не должны учитываться дважды поверх свежих итогов. `thread_read_changed` без `thread_id`, смена CRT на off и DM-треды не должны оставлять «залипшее» упоминание. — Task 5: `TestThreadMentionsSurviveRefreshWithoutDoubleCount`, `TestAllThreadsReadRereadsTotals`, `TestThreadMentionsVanishWhenCRTTurnsOff`.

### Task 1: Фейк и REST — эндпоинты и события тредов, факты API

**Files:** `internal/mmfake/chat.go`, `server.go`, `ws.go`, новый `internal/mmfake/threads.go` (+ `threads_test.go`); `internal/mm/rest/` (новый `threads.go` + тест); `internal/mm/model/model.go` (`PostList.HasNext`, `TeamUnread`, `ThreadResponse`, `ThreadTotals`); `internal/mm/ws/decode.go` (+ тест); `cmd/spk-mm-client/browser.go` (тест-API) (+ `browser_test.go`); `docs/research/2026-09-24-mattermost-api-facts.md` (новый раздел «8. Треды»); `AGENTS.md` (список тест-API фейка в «Things that bite»).

**Interfaces:**
- Produces:
  - REST: `type ThreadQuery struct { PerPage int; FromCreateAt int64; FromPost string; CollapsedThreads bool }`.
  - `func (c *Client) PostThread(ctx context.Context, rootID string, q ThreadQuery) (model.PostList, error)` — всегда `direction=up`, `PerPage` 0 → 60, больше 200 → 200.
  - `func (c *Client) MarkThreadRead(ctx context.Context, teamID, rootID string, ts int64) error`.
  - `func (c *Client) TeamsUnread(ctx context.Context, includeCollapsed bool) ([]model.TeamUnread, error)`.
  - `func (c *Client) ThreadTotals(ctx context.Context, teamID string, excludeDirect bool) (model.ThreadTotals, error)`.
  - model: `PostList.HasNext *bool json:"has_next,omitempty"`.
  - ws: `DecodeThreadUpdated(e) (ThreadUpdated, error)` — `data.thread` это JSON-строка `ThreadResponse`, плюс `previous_unread_mentions`/`previous_unread_replies`.
  - ws: `DecodeThreadReadChanged(e) (ThreadReadChanged, error)` — `thread_id` может отсутствовать.
  - Фейк: `(*Server).SetCollapsedThreads(mode string)`, `ThreadReads() []ThreadRead`, `Following(rootID, username string) bool`, `SeedThread(channelID, username string, replies int) string`.

- **Фейк — эндпоинты** (права — членство в канале, как у `channelPosts`; `{uid}` принимает `me`):
  - `GET /api/v4/posts/{pid}/thread` — `perPage` (без него — весь тред, как у сервера; больше 200 → 400), `direction=up|down`, `fromCreateAt`, `fromPost` (без `fromCreateAt` → 400), `collapsedThreads`. Ответ `{order, posts, has_next}`: `order[0]` — запрошенный пост, дальше страница ответов (`up` — по убыванию `create_at`, затем id). `has_next` — через `perPage+1`. Удалённые и строки истории правок не отдаются. `collapsedThreads=true` с id ответа → 400. Удалённый или неизвестный корень → 404, не член канала → 403.
  - `GET /api/v4/users/{uid}/teams/unread?include_collapsed_threads=true` → `[{team_id, msg_count, mention_count, msg_count_root, mention_count_root, thread_count, thread_mention_count, thread_urgent_mention_count}]`. Тредовые поля — только по подписанным тредам команды, без DM/GM (`ThreadTeamId IN teams`), и только если CRT не `disabled`.
  - `GET /api/v4/users/{uid}/teams/{tid}/threads?totalsOnly=true[&excludeDirect=true]` → `{total, total_unread_threads, total_unread_mentions, total_unread_urgent_mentions, threads: []}`. DM/GM-треды входят, если нет `excludeDirect`. `totalsOnly` вместе с `threadsOnly` → 400.
  - `PUT /api/v4/users/{uid}/teams/{tid}/threads/{rid}/read/{ts}`:
    - нет подписки на тред → 404;
    - иначе ставит `last_viewed=ts`, пересчитывает `unread_mentions` (упоминания в ответах после `ts`);
    - публикует `thread_read_changed` `{thread_id, timestamp, unread_mentions, unread_replies, previous_unread_mentions, previous_unread_replies, channel_id}` с broadcast `{user_id, team_id}`;
    - записывает вызов в `ThreadReads`, отвечает `ThreadResponse`.
- **Фейк — поведение постов:**
  - `createPostLocked` с `root_id` проверяет, как сервер (`app/post.go:299–306`): корень существует, не удалён, в том же канале, сам не ответ; иначе 400 `api.post.create_post.root_id.app_error`.
  - Пост ответа в ответе и в `posted` несёт `reply_count` треда: неудалённые ответы, включая этот.
  - Корень получает `UpdateAt = create_at` ответа, `LastReplyAt`, `ReplyCount`.
  - Запись треда (появляется с первым ответом) и подписки: автор ответа, автор корня, упомянутые. `following`, `last_viewed` (автору — время его ответа), `unread_mentions`.
