# Этап 3, часть 1б — просмотрщик (текст, зум) и список загрузок

Источник — живая проверка пользователя 2026-09-26 после части 1 (`docs/plans/2026-09-25-stage3-avatars-previews-reactions.md`):
1. В просмотрщике текст сильно ужат по ширине (`max-w-5xl`).
2. Лимит текста 64 КиБ мал — «хоть 1 МБ»; нужен нормальный поиск по тексту.
3. Картинкам не хватает зума колесом мыши и перетаскивания зажатой ЛКМ.
4. Для скачанных файлов — меню как в браузерах: список загрузок с действиями «Открыть», «Открыть папку с файлом».

Спека — `docs/specs/2026-09-24-spk-mattermost-design.md`; правила — `AGENTS.md`. Решения контроллера (пользователь их не уточнял — записаны в реестр SDD как Ruling):
- Фрагмент в ленте по-прежнему берёт первые 64 КиБ (ему нужно 8 строк; не качать мегабайт на каждый лог в ленте). Просмотрщик берёт до 1 МиБ отдельным запросом.
- Просмотрщик сразу открывает оригинал картинки (`src=file`) — решение пользователя 2026-09-26: «если я открываю картинку, то сразу хочу оригинал смотреть». Пока оригинал грузится, показывается уже загруженное превью (без пустого экрана); оригинал вне медиа-лимитов или с ошибкой загрузки — остаётся превью.
- Список загрузок хранится в SQLite (последние 100 записей) и переживает перезапуск, как в браузере; удалённый с диска файл помечается «Файл удалён», действия недоступны.
- «Открыть папку» — выделить файл в файловом менеджере через D-Bus `org.freedesktop.FileManager1.ShowItems` (Nautilus/Nemo/Dolphin/Thunar это умеют), при ошибке — `xdg-open` каталога. Только по действию пользователя, с таймаутом; никаких вызовов системных сервисов на старте.
- «Открыть» из списка подчиняется тому же allowlist, что и кнопка у вложения; для прочих типов в строке только «Открыть папку».

## Global Constraints

Те же, что у части 1 (`.superpowers/sdd/2026-09-25-…/constraints.md` сохранены в `constraints.md` рабочего каталога этого плана): Go 1.26, Wails v3.0.0-beta.25; `go test -race`, `golangci-lint` для обоих наборов тегов, `gofmt`; фронтенд `pnpm test && pnpm lint && pnpm build`; i18n ru/en с паритетом ключей; доступность (aria-label у кнопок-иконок, клавиатура); UI ходит только в `api.API` и `/media/`; все кэши и списки ограничены, без роста памяти; ничего блокирующего на старте; коммиты — репозиторная идентичность, без amend и Co-Authored-By; Playwright-контексты закрываются в том же вызове; живой dev-клиент пользователя и `/opt/Mattermost` не трогать, pkill/killall запрещены, desktop-бинарь `build/bin/spk-mm-client-desktop` не пересобирать (пользователь его запускает) — для проверки сборки desktop собирать во временный путь под `.agents/tmp`.

### Task 1: Полный текст до 1 МиБ в Go

**Files:** `internal/media/media.go`, `internal/media/media_test.go` (и где нужно — `internal/api/media*.go`).

- Вид `text` получает параметр `?full=1`: без него — как сейчас (первые `TextLimit` = 64 КиБ, Range), с ним — первые `TextFullLimit = 1 << 20` байт (Range `bytes=0-1048575`), ключ кэша различает варианты. Заголовок `X-Truncated: 1`, если файл длиннее лимита (как сейчас). Проверка UTF-8 и 415 для бинарного — та же; обрезка по границе руны — та же, что сейчас.
- Любые другие значения `full` — 400 (как прочие неверные параметры).
- Тесты: `?full=1` отдаёт больше 64 КиБ и не больше 1 МиБ, `X-Truncated` у файла > 1 МиБ, отдельная запись кэша, неверный параметр — 400. Фейк (`internal/mmfake`) — при необходимости текстовый файл > 1 МиБ в сиде для e2e (например, `big.log` ~1.2 МиБ в Off-Topic); не ломать существующие e2e (число вложений в постах сида).

### Task 2: Просмотр текста — во всю ширину, 1 МиБ, поиск

**Files:** `frontend/src/components/Viewer.tsx`, `Viewer.test.tsx`, `textFile.ts`, `TextSnippet.tsx` (без изменения поведения), `frontend/src/i18n.ts`.

- `FullText` грузит `mediaURL(…, 'text', id, { full: '1' })`; фрагмент в ленте — без `full`.
- Ширина: панель текста занимает всю ширину окна просмотрщика за вычетом отступов (без `max-w-5xl`), строки не переносятся, горизонтальная прокрутка.
- Плашка обрезки — «Показаны первые 1 МБ» / «Showing the first 1 MB» (i18n-ключ вместо захардкоженного 64).
- Поиск: строка поиска в шапке текстового просмотра (поле + «n из m» + кнопки «предыдущее/следующее» с aria-label). `Ctrl+F` фокусирует поле (перехватить у webview), `Enter`/`Shift+Enter` — следующее/предыдущее (по кругу), `Esc` в поле с текстом — очистить, в пустом поле — закрыть просмотрщик (как раньше). Регистронезависимо, подстрока. Все совпадения подсвечены, текущее — ярче и прокручено в видимую область (по вертикали и горизонтали). Производительность: 1 МиБ текста, частый запрос (например «a») — подсветку ограничить (например, первые 5000 совпадений, счётчик честный «5000+»), ввод с дебаунсом ~150 мс; UI не должен подвисать заметно (проверить на 1 МиБ в браузере, записать время).
- ←/→ по-прежнему листают файлы поста, но не когда фокус в поле поиска.
- Тесты: ширина (нет `max-w-5xl`), `full=1` в URL, поиск: счётчик, переход по Enter/Shift+Enter, подсветка текущего, Esc-логика, стрелки в поле не листают.
- Скриншоты browser mode (по «Процедуре скриншота» части 1): текстовый просмотр во всю ширину с активным поиском.

### Task 3: Картинки — зум колесом и перетаскивание

**Files:** `frontend/src/components/Viewer.tsx` (или новый `ImageZoom.tsx`), тесты, `i18n.ts`.

- Исходно — «вписать» (как сейчас). Колесо мыши — зум вокруг курсора (шаг ~×1.2, пределы: от «вписать» до 8× натурального размера оригинала/превью); `Ctrl`+колесо и тачпад-пинч (wheel с ctrlKey) — так же. Зажатая ЛКМ и перетаскивание — панорама, когда картинка больше окна; курсор `grab`/`grabbing`. Двойной клик — переключение «вписать» ↔ 100 %. Клавиатура: `+`/`-`/`0` (0 — вписать). Индикатор масштаба (например, «150 %») в шапке, кнопка «Вписать».
- Клик по фону закрывает просмотрщик только если это не конец перетаскивания (перетаскивание не должно закрывать).
- При переходе ←/→ масштаб сбрасывается на «вписать».
- Просмотрщик сразу грузит оригинал (`mediaURL(…, 'full', id, { src: 'file' })`), если он растровый и в пределах лимитов (`IMAGE_FILE_MAX`, GIF — как сейчас); пока он не загружен, на его месте показывается превью (`src=preview`, если есть) с тем же вписыванием, затем подмена без скачка (сохранить масштаб и видимую точку, если пользователь уже зумил); ошибка оригинала — остаться на превью молча. Файлы без превью и в пределах лимитов — сразу оригинал, как сейчас.
- Реализация через CSS `transform` на `<img>` (translate + scale), без перерисовки ленты; `will-change` только во время жеста.
- Тесты (vitest): wheel меняет масштаб и сохраняет точку под курсором (проверить вычисление через экспортируемую чистую функцию), drag сдвигает, drag не закрывает, двойной клик, клавиши, сброс при смене файла, оригинал запрашивается сразу, превью — заглушка до загрузки, ошибка оригинала оставляет превью.
- Скриншоты browser mode: увеличенная картинка со смещением и индикатором масштаба.

### Task 4: Список загрузок в Go — хранение, прогресс, «Показать в папке»

**Files:** `internal/store/migrations/0003_downloads.sql`, `internal/store/downloads.go` (+ тест), `internal/api/files.go`, `internal/api/api.go`, `internal/api/transport/http.go`, `wails.go`, `http_test.go`, `internal/api/events.go` (или где события), `cmd/spk-mm-client/browser.go` (test-API), `cmd/spk-mm-client/run_desktop_wails.go`, новый `internal/desktop/showitem*.go` или `internal/api/reveal.go`.

- Таблица `downloads(id INTEGER PRIMARY KEY, server_id, file_id, name, path, size, mime, started_at, finished_at, state TEXT /* downloading|done|failed */, error TEXT)`; хранить последние 100 (обрезка при вставке). На старте незавершённые (`downloading`) помечаются `failed` («прервано»). Чтение списка — только по запросу UI (не на пути старта).
- Каждая загрузка (`DownloadFile` и `OpenFile`, включая присоединившиеся к общей — одна запись на реальную загрузку; повторное «Скачать» того же уже сохранённого файла в сессии — новая запись не нужна, достаточно поднять существующую наверх) создаёт/обновляет запись. Прогресс: событие `downloads_changed` (через существующий механизм событий UI) не чаще ~4 раз в секунду на загрузку с `received` байт; итог — `done` с путём или `failed` с кодом ошибки.
- API: `Downloads(ctx) ([]DownloadView, error)` — список (новые сверху) с полем `exists` (файл на месте и того же размера — `os.Stat`, дешево для 100 записей); `OpenDownload(ctx, id) (opened bool, err)` — allowlist как у `OpenFile`; `RevealDownload(ctx, id) error` — показать в папке; `RemoveDownload(ctx, id)`, `ClearDownloads(ctx)` (только завершённые/сбойные, идущие не трогать). Коды ошибок: `no_file` (файла нет на диске).
- `Reveal`: D-Bus `org.freedesktop.FileManager1.ShowItems([file://…], "")` на session bus с таймаутом ~2 с (библиотека — `github.com/godbus/dbus/v5`, если её ещё нет — добавить; проверить, нет ли уже D-Bus клиента в зависимостях, например у уведомлений); ошибка/нет сервиса — `xdg-open <каталог>` через тот же opener, что у «Открыть». Browser mode и тесты — записывающий заглушкой (как `RecordingOpener`), test-API `GET /api/_test/revealed-files`.
- Транспорты HTTP (`POST /api/Downloads`, `/api/OpenDownload {id}`, `/api/RevealDownload {id}`, `/api/RemoveDownload {id}`, `/api/ClearDownloads`) и Wails — рядом с существующими, за теми же guard.
- Тесты: миграция, обрезка до 100, прерванные → failed при открытии store, прогресс-события троттлятся, singleflight даёт одну запись, `exists` false после удаления файла, OpenDownload соблюдает allowlist, Reveal падает на xdg-open при ошибке D-Bus (через интерфейс/заглушку), транспорты.

## Дополнение пользователя 2026-09-27: превью видео, аудио и markdown-файлов

Пользователь: «следующим бери в работу превью видео и аудио», «и md файлов» — снимает их из бэклога. Порядок выполнения: Task 3 → **Task 7 → Task 8 → Task 9** → Task 4 → Task 5 → Task 6 (e2e и документы — последними, покрывают и новое).

Решения контроллера:
- Видео/аудио играют встроенные `<video controls>` / `<audio controls>` webview (WebKitGTK → GStreamer в desktop). Данные идут только через `/media/` того же origin (правило «UI не ходит к серверу»): новый вид `stream` — сквозная передача с поддержкой `Range` (206) от `GET /api/v4/files/{id}`, **без** записи в дисковый кэш (файлы большие; кэш 256 МиБ не для них) и без буферизации в памяти (копирование потоком). Лимит запросов 10/с общий — перемотка делает запросы, это приемлемо; один поток на элемент.
- Типы: видео `mp4, webm, mov, m4v, ogv, mkv`; аудио `mp3, ogg, oga, opus, wav, flac, m4a, aac` — по расширению и mime. Что webview не может воспроизвести (нет кодека GStreamer) — событие `error` у элемента → карточка файла (как у картинок).
- В ленте: видео — рамка с постером-заглушкой (иконка ▶, имя, размер; фиксированный размер до загрузки, как у картинок — лента не прыгает) и `preload="none"`; воспроизведение по клику прямо в ленте; «⤢» — в просмотрщике крупно. Аудио — компактный плеер в строке файла (`preload="none"`). Одновременно играет один элемент: запуск другого ставит предыдущий на паузу. Уход элемента из DOM (виртуализация ленты, смена канала) — остановка и освобождение (`removeAttribute('src'); load()`), иначе WebKit держит декодер и буферы (урок 13b про память).
- Markdown-файлы (`.md`, `.markdown`): фрагмент в ленте — отрендеренный markdown (существующий компонент `Markdown` поста: удалённые картинки — ссылками, ссылки — в системный браузер), высота фиксирована как у текстового фрагмента; в просмотрщике — рендер на всю ширину с переключателем «Исходный текст» (тогда `TextView` с поиском из Task 2). Источник — тот же `text` (`full=1` в просмотрщике).

### Task 7: Спайк и потоковая отдача видео/аудио в Go

**Files:** `internal/media/media.go` (+ тесты), `internal/api/media.go` при необходимости, `internal/desktop/media.go` (+ тест), `internal/mmfake` (Range у файлов уже есть; сид — короткое видео и аудио), `docs/spikes/2026-09-24-stage1-spikes.md` (новый спайк S-media).

- **Спайк сначала (записать в spikes):** проходят ли запросы `<video>`/`<audio>` WebKitGTK к `wails://…/media/…` через `AssetOptions.Handler` с заголовком `Range`, и играет ли webview mp4 (H.264/AAC) и webm (VP9/Opus) из такого источника. Проверка — временная локальная сборка во временный путь (не `build/bin/spk-mm-client-desktop`!), одна копия, свой `SPK_MM_CLIENT_HOME`, без ввода X11: страница из фейка с `<video autoplay muted>` и проверка `currentTime > 0` через лог/JS→Go (или `ended`), запись результатов (какие кодеки есть в системе: `gst-inspect-1.0 | grep -i -E 'avdec_h264|vp9|opus|aac'`). Если custom scheme не поддерживает Range/стриминг — предложить и реализовать запасной путь (например, `/media/stream` в desktop отдавать через отдельный loopback-HTTP сервер с одноразовым токеном в URL, привязанным к сессии, и CSP/заголовками) — это решение записать в спайк и отчёт; если нужно выбрать между вариантами с разными компромиссами безопасности — остановиться и доложить (NEEDS_CONTEXT).

Только пока воркер live (как прочие медиа). 401 → сигнал авторизации (как у прочих).

### Решение пользователя 2026-09-27 по Task 7: вариант A — loopback HTTP для медиа-потока

Спайк S6: `<video>/<audio>` WebKitGTK не играют из `wails://` (у GStreamer нет обработчика схемы). Пользователь выбрал вариант A. Требования:
- Отдельный HTTP-сервер только в desktop-режиме, слушает `127.0.0.1:0` (случайный порт), поднимается лениво — при первом запросе UI адреса потока (не на пути старта), живёт до выхода приложения, закрывается при остановке.
- Токен сессии: 32 случайных байта (crypto/rand), base64url, в пути URL: `http://127.0.0.1:<port>/<token>/stream/<srv>/<fileID>`; сравнение за постоянное время; токен не пишется в логи (логировать путь без него), новый при каждом запуске.
- Защиты: проверка `Host` = `127.0.0.1:<port>` (DNS rebinding), только `GET`/`HEAD`, никакого CORS (`Access-Control-*` не отдаётся), `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`, `Cache-Control: private`; отдаются только медиа-типы из белого списка Task 7 и только пока воркер сервера live; прочие пути — 404.
- Обработчик — тот же вид `stream` из `internal/media` (Range passthrough, поток без кэша, отмена закрывает upstream, 401 → сигнал авторизации); в browser mode поток идёт через обычный `/media/<srv>/stream/<id>` на существующем loopback-сервере (там webview — браузер, `<video>` с http работает).
- UI получает базовый адрес потока методом API (`MediaStreamBase(ctx) (string, error)` — в desktop адрес loopback-сервера с токеном, в browser mode — `/media`), не собирает его сам.
- Тесты: неверный токен/Host/метод → 404/403/405, Range 206, отмена, закрытие при остановке, ленивый старт (до запроса порт не открыт), токен не попадает в логи.
