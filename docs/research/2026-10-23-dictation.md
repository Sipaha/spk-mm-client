# Диктовка через SPK LAIHub

В композерах канала и треда есть кнопка микрофона. Первый клик включает
микрофон, второй завершает запись и распознаёт её локально. Результат
добавляется в конец актуального черновика и сохраняется обычным механизмом
черновиков. Можно продолжать редактировать текст во время записи/распознавания.
Отправка сообщения — отдельное действие; во время диктовки она отключена.
Аудиофайл не прикрепляется к сообщению и не записывается на диск клиентом.

Максимальная запись — 60 секунд: затем распознавание начинается автоматически.
«Отменить диктовку» отменяет также ожидающее распознавание. Уход из канала,
закрытие треда, скрытие приложения и удаление корня треда освобождают микрофон
и отменяют запрос. Диктовка в другом композере отменяет предыдущую; поздний
ответ не меняет чужой черновик. Отказ в доступе к микрофону, отключение
устройства и недоступность модели показываются в композере, не очищая текст.

## Подключение

SPK LAIHub должен быть запущен с речевым API:
`--speech-listen 127.0.0.1:8095`. В LAIHub установлен GigaAM; модель загружается
его собственным менеджером по запросу. MM-клиент не запускает/не устанавливает
модели и не управляет процессом LAIHub. GigaAM распознаёт русский язык,
результат может требовать правки пробелов и пунктуации.

По умолчанию Go обращается к `http://127.0.0.1:8095/v1/audio/transcriptions`.
Для отдельного локального экземпляра можно задать переменную окружения
`SPK_MM_CLIENT_SPEECH_URL=http://127.0.0.1:<port>` до запуска клиента.
Разрешён только HTTP с числовым loopback IP и без пути/credentials/query;
renderer не может передать свой адрес. Прокси окружения и редиректы отключены,
токены/куки Mattermost в этот запрос не попадают.

Web Audio захватывает моно звук и преобразует в PCM16 WAV, 16 kHz,
0.1–60 секунд. Go проверяет заголовок и размер, затем отправляет multipart
`file=dictation.wav`, `language=ru`. Обмен WebView→Go — base64 через
`TranscribeAudio`, одинаковый в Wails и browser-режиме. У HTTP-маршрута
собственный лимит 3 MiB, обычные JSON-вызовы сохраняют лимит 1 MiB.
Заголовочная авторизация и OriginGuard действуют и для нового маршрута.
Запрос отменяется вместе с вызывающим или закрытием Service; дедлайн — 90 с.

## Проверка

Регрессии: `frontend/src/components/ComposerDictation.test.tsx`,
`frontend/src/dictationAudio.test.ts`, `internal/speech/transcribe_test.go`,
`internal/api/transport/http_test.go` (`TestTranscriptionBodyLimitAndAuthentication`).
Покрыты сохранение актуального черновика, явная отправка, поздний ответ после
отмены, позднее разрешение микрофона после ухода, отказ в доступе, автолимит,
формат WAV, полная минута аудио, лимиты тела, отсутствие credentials,
запрет внешних адресов/редиректов и отмена HTTP-запроса.

`tests/e2e/dictation.spec.ts` по умолчанию использует синтетический микрофон
Chromium и подставной ответ распознавания. Для настоящего LAIHub задать
`E2E_DICTATION_LIVE=1` и `E2E_DICTATION_AUDIO=<абсолютный путь к русскому PCM WAV>`.
При loopback-прогонах HTTP(S)/ALL_PROXY нужно отключить, а NO_PROXY включить
`127.0.0.1,localhost,::1` явно: CIDR-исключение не все Node-клиенты понимают.
Все TMPDIR/профили/скриншоты направлять в Solution `.tmp`.

2026-10-23 полный browser-путь с настоящим GigaAM прошёл в канале и треде:
реальный захват/ресемплинг тестового WAV, сохранение после reload, отмена и уход.
Native Wails/WebKitGTK тоже распознал русскую фразу через настоящий Go binding
и LAIHub. В native-проверке микрофон заменён собственным Web Audio MediaStream
с синтезированной фразой; физический микрофон пользователя не записывался.
Тестовый клик выполнен XTest на отдельном Xvfb; вид записи и черновика проверен
по скриншотам. Windows проверяется cross-build/vet; native Windows/macOS
и аппаратный микрофон этим прогоном не проверены.
Операционная история проверок находится в задаче
`spk-mm-client-dictation-20261023`; временные результаты — Solution
`.tmp/mm-dictation/`. README не менялся.

## macOS-пакеты

В app bundle включён `NSMicrophoneUsageDescription` с объяснением диктовки
через локальный SPK LAIHub. Этот ключ необходим для доступа к микрофону
([Apple: media capture authorization](https://developer.apple.com/documentation/bundleresources/requesting-authorization-for-media-capture-on-macos)).
Проверяется как контракт метаданных, так и реальный `Info.plist` нативного
архива. Это не заменяет проверку физического микрофона/разрешения TCC на
пользовательском Mac. Hardened runtime и sandbox этим выпуском не включаются;
схема ad-hoc-подписи остаётся прежней.
