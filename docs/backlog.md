# Бэклог (низкий приоритет)

Приоритет проекта — рабочий клиент, которым можно заменить официальный
(решение пользователя 2026-09-24). Мелочи ниже делаются, но после ядра.

- **Настройка языка UI** «Как в системе / Русский / English». Сейчас язык
  следует языку сообщений системы (gettext: `LANGUAGE`, `LC_ALL` >
  `LC_MESSAGES` > `LANG`) — см. `docs/spikes/2026-09-24-stage1-spikes.md` S5.
- Мелочи из ревью этапа 1 (`ErrServerExists` уже закрыт — теперь sentinel-ошибка
  с `errors.Is`, не сравнение текста): временный home e2e не удаляется; поздно
  стартовавший notifier может оставить D-Bus-соединение; тело успешного
  REST-ответа без `out` не дочитывается (новое TCP-соединение на каждый такой
  запрос вместо переиспользования keep-alive); просроченные SSO-входы чистятся
  только в `Complete`; холодный старт по `mmauth://` (приложение не запущено)
  всегда `no_pending_login`, а токен виден в `/proc/<pid>/cmdline`.
- Мелочи из финального ревью этапа 2 (не исправлены, по задачам):
  T1 — ветка `"null"` в `FlexString`; `go 1.26.0` в go.mod. T3 — `NextPostID`
  фейка. T4 — дублированный код 401 в фейке; припаркованные WS-сессии фейка
  не удаляются. T5 — битый JSON `mentions` молча игнорируется; слабые
  ws-тесты; нет `ErrClosed`; sleep в тестах; `eventBuffer` — переменная
  пакета. T6 — запасной вариант для канала вне категорий; нет тестов
  `Me`/`SetStatus`/`TeamIDs`. T7 — pending-ответы CRT в ленте канала; счётчик
  ответов не уменьшается при удалении; `MergeSince` пропускает загруженную
  историю; архивный открытый канал навсегда «Синхронизация»; `SetWindow`
  затирает более новый локальный счётчик ответов. T8 — защита `Restore` на
  непустом сервере; нет теста на битый JSON снимка. T10 — лишнее
  переподключение после буферизованного nudge; повтор fetch раз в 10 с в
  офлайне/`needs_reauth`; тесты с фиксированными паузами; `Stop`
  последовательный. T11 — уведомление после закрытия / «(+N)» после
  обрезки; `ChannelView` строится дважды; `newFixture` не закрывается; нет
  тестов на маппинг ошибок. T12 — дублированные подписи состояний; состояние
  подключения в рейле только в title. T13 — нет проверки схемы `title_link`.
  T14b — контраст при наведении. T15 — `fake.Close` до `svc.Close`; точка
  трея перекрывает пузырь; передача трея не протестирована; повторное
  использование порта devfake; `app.Quit` после раннего возврата; `badgeMu`
  удерживается во время колбэков.
- Гонка двух REST-чтений при ресинке: упоминание, начисленное сервером между
  чтением каналов и членств (или, у реального сервера, между сохранением
  поста и увеличением счётчиков упоминаний), может посчитаться дважды или
  потеряться; повторное чтение каналов ловит первый случай и запрашивает ещё
  один ресинк, второй на клиенте не обнаружить.
- Припарковано в финальном ре-ревью этапа 2 (не исправлено): если `SetWindow`
  очищает `s.older` целиком через `DeleteFunc`, `olderComplete` не сбрасывается
  — возможен ложный «истории больше нет» (редкий случай); «достаёт ли новая
  страница до начала старого окна» в `SetWindow` решается по `CreateAt`, а не
  по ID поста (грань — посты в одну и ту же миллисекунду); бэкофф повтора
  обновления метаданных (5→60 с) не сбрасывается при новом bootstrap сессии —
  таймер повтора привязан к воркеру, а не к сессии. —
  `internal/state/posts.go` (`SetWindow`), `internal/mmsync/worker.go`
  (`retryRefresh`).

## Этап 3, не вошло в часть 1

Решения пользователя 2026-09-25 (Task 13, addendum) — что осталось за
пределами «аватары/статусы, превью картинок и текста, реакции»:

- Превью видео, аудио и markdown-файлов — решение пользователя «в todo».
- Выбор оттенка кожи в пикере эмодзи.
- Имена отреагировавших во всплывающей подсказке чипа реакции.
- Число участников у групповых сообщений (GM) в сайдбаре — нужна статистика
  канала с сервера, сейчас не запрашивается.
- Иконки вебхуков (`override_icon_url`) — внешний URL, не проходит через
  `/media/`.
- Уменьшенные превью в Go для форматов, кроме JPEG/PNG (WebP/BMP идут в
  ленте как есть, без серверного даунскейла) и EXIF-поворот оригиналов без
  серверного превью — `internal/media`.
- **Позже, после согласования с пользователем**: треды (CRT, панель), поиск,
  загрузка файлов, автодополнение `@ ~ :`, Ctrl+K.

Мелочи из реализации части 1 (deferred, по задачам — не исправлены, кроме
явно отмеченных пользовательских решений выше):

- T3 (медиа): лента не масштабирует gif/webp/bmp — большие анимации/картинки
  этих форматов идут в ленте в исходном размере, до 24 Мпикс без сжатия —
  `internal/media`. Догрузка картинок с `src=file` в ленте делит семафор
  декодирования с запросами превью и может ненадолго придержать очередь
  аватаров (переходный всплеск ~150 МБ на широкой ленте с исходниками).
- T4 (аватары/статусы/эмодзи): cookie `spk_media` в browser-режиме несёт
  полный API-токен (так предписывал план) — стоит завести отдельный секрет
  только для медиа. Список эмодзи сервера грузится воркером один раз за
  сессию — новый кастомный эмодзи, добавленный сервером офлайн, появится в
  пикере только после переподключения, не сразу. `EmojiID` может вернуть id
  уже удалённого (`DeleteAt != 0`) эмодзи.
- T5 (статусы): присутствие не чистится при уходе сервера из «живого»
  состояния — точка статуса может на время застрять «как было» вместо
  «оффлайн».
- T6 (UI статусов): цвет ободка точки статуса фиксирован под цвет строки в
  состоянии покоя — на наведённой/выбранной строке виден шов (так предписывал
  план).
- T7 (скачивание/открытие): дедупликация файлов по имени доверяет размеру из
  `stat` (не различает файл/каталог); параллельные скачивания одного и того
  же файла могут создать две копии вместо одной. Санитизация имён не
  покрывает все зарезервированные имена Windows (`COM0`/`LPT0`/`CONIN$`) и
  надстрочные символы. MOTW/quarantine-атрибут скачанных файлов — только с
  этапа 4 (Windows/macOS).
- T8 (просмотрщик/карточки): полупрозрачная подложка просмотрщика оставляет
  ленту видимой позади — можно спутать с частичной загрузкой.
- T10 (реакции): если все 4 попытки повтора исчерпаны, откат идёт молча — UI
  не показывает пользователю, что реакция не применилась (кроме самого факта
  отката чипа). Редкие грани: коррекция после «неуверенного» запроса при
  повторном bootstrap может на миг перезаписать оптимистичное состояние;
  переключения во время падающего сервера могут обойти бэкофф (ограничено
  `reactAttempts`); порядок сохранения «Недавних» эмодзи при гонке не
  гарантирован.
- T12 (пикер эмодзи): диалог пикера не помечен `aria-modal` и не ловит `Tab`
  в фокус-ловушку — клавиатурная навигация выходит за пределы диалога.
